# LitScout v0.1 round 2 brief

Written 2026-11-11. Round 1 is described in `docs/v0.1-build-report.md`; all rules in `docs/v0.1-build-brief.md` still apply, except where this brief explicitly allows live network reads. Work on `feat/v0.1` in this worktree.

## Goal

Close the open items from round 1 that need no account, key or deploy:

1. **Live compatibility of the keyless sources.** Call the real public APIs of Semantic Scholar (keyless, 1 request every 3 s at most), OpenAlex (keyless, no contact email), arXiv (1 request every 3 s, one connection) and OpenReview (respect `x-ratelimit-*`) with a handful of representative requests per adapter. Compare the real response shapes with the synthetic fixtures. Save small, scrubbed recordings as new fixtures (strip any request headers, cookies and tokens; keep only what the tests need), add regression tests that use them, and fix any adapter that does not handle the real shape. CORE needs a key: skip it and say so in the report.
2. **P5 data.** Read `~/GitHub/daily-arXiv-ai-enhanced/docs/measurements/` (read only: `arxiv-coverage.md`, `venues.py`, `verify.py`). Rebuild the 600-paper sample the way that measurement did (15 venues, 40 unique papers each, seed 7, ICCV 2023 and the other venues 2024). If the original sample cannot be reproduced exactly, build the closest faithful sample and record every difference. Record the S2 and OpenAlex title-query replies into the snapshot format in `eval/README.md`, at the polite rates above. Before the run, check how many OpenAlex credits a search costs and keep total use under 80% of the keyless daily allowance; if that cannot fit, record as much as fits and report the shortfall. Run `npm run test:eval` on the snapshot and report the score per venue. Do not tune the evaluator or the matcher to the sample after seeing its results; if a matcher bug is found, fix it with a test that does not depend on the sample, and report the score before and after.
3. **Venue table spot-check.** Download the official CCF and ICORE files again locally (outside git), parse them with the shipped parser, and check 40 rows against the source documents: journals, conferences, wrapped titles, renamed venues, missing DBLP links. Fix parser errors with tests on small invented fixtures. Record the results in `docs/venue-data-licence.md` or a new `docs/venue-parse-check.md`. Do not commit the downloaded files or the parsed table.
4. **Small fixes.** The comment in `src/auth/crypto.ts` says the pairing alphabet has 31 symbols; it has 32. Fix it.

## Rules

- Total live requests: keep them modest (the P5 recording plus at most about 50 compatibility requests per source). Never parallelise requests to the same source.
- Recordings committed to git must be small and contain only public bibliographic data. The full P5 snapshot may be committed only if it is under about 5 MB; otherwise keep it outside git, commit a script that reproduces it, and say where it lives.
- Run `npm test`, `npm run test:coverage`, `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run build` and `npm run test:worker` before each commit. Coverage stays at 80% or more on all four metrics.
- Same prohibitions as round 1: no push, PR, publish, login or deploy; no edits outside this worktree.

## Report

Append a "Round 2" section to `docs/v0.1-build-report.md`: what changed (commit hashes), each live-compatibility finding, the P5 score per venue and overall with the sample's provenance and any differences from the original, the venue spot-check result, and what is still open.
