# LitScout v0.1 build brief

Written 2026-11-11 for the agent that builds v0.1. Read `ROADMAP.md`, `docs/design.md` and `docs/product.md` first; they are the specification. This brief adds the decisions taken on 2026-11-11 and the working rules.

## Goal

Implement ROADMAP phases P0, P1, P2, P3a-P3e and P5, plus the CI and README parts of P4, on the branch `feat/v0.1` in this worktree. Done means: all seven tools from design.md §5 work against mocked upstreams, the CLI commands exist and are tested with `wrangler` mocked, `npm test` passes, coverage is at least 80%, and `npm run typecheck` (strict TypeScript) and the linter are clean.

## Decisions (2026-11-11)

1. **Semantic Scholar without a key is supported** as a slow mode: 1 request every 3 s. If the expected wait is above about 10 s, S2 is skipped and reported in `sources_skipped` with the reason. With a key: 1 request per second.
2. **Venue table licence.** Before bundling any CCF or ICORE data, read their published terms and record the finding in `docs/venue-data-licence.md` with links. If redistribution is not clearly allowed, do not ship the data in the package: ship a fetch script that `litscout deploy` runs to download the table into the user's own deployment, and ship tests with a tiny synthetic fixture only.
3. **Prototype source:** `~/GitHub/scholar-mcp` (read only; never modify it). Copy its code in as P0.

## P0 scrub (required before the first commit that contains prototype code)

- Remove the GitHub OAuth path entirely (`src/auth/github.ts`, `GITHUB_*` secrets, `ALLOWED_GITHUB_USERS`, the allowlist test).
- No personal identifiers anywhere: remove personal handles, real hosted endpoints, account and KV ids, and email addresses. Repository URLs are allowed only in package metadata and README. Keep only a configuration template; the CLI generates the actual config locally.
- Run the prescribed personal-identifier scan before every commit and resolve every hit. The build log records this check.

## Working rules

- Test-driven: write the test, see it fail, implement, see it pass. Mock every upstream with recorded fixtures; unit tests make no network calls. Live tests stay in a separate opt-in config and are not run.
- Commit after each phase with a conventional message (`feat: ...`, `test: ...`, `docs: ...`). No co-author lines, signatures or emoji. Commits use the git identity already configured in this worktree.
- Keep files focused (about 200-400 lines, 800 at most) and functions short. Prefer immutable updates.
- Keys never appear on a command line, in logs or in test output. `wrangler secret bulk` reads a temporary file with mode 0600 that is deleted afterwards.
- Pairing state lives in a Durable Object, never KV. Compare the management token and pairing code in constant time.
- Never send a contact email upstream by default.

## Forbidden

- `git push`, opening PRs, `npm publish`, `npm login`, `wrangler login`, `wrangler deploy` or any command that changes a Cloudflare, npm or GitHub account.
- Editing anything outside this worktree.
- Calling the real Semantic Scholar, OpenAlex, CORE, arXiv or OpenReview APIs from tests. Reading their public documentation pages to check request and response shapes is fine.
